## 2. مصدر بيانات كل قسم

كل محتوى الأقسام في ملفات JSON داخل `src/content/`، ويُستورد وقت البناء. أي تعديل يتطلب إعادة البناء في الإنتاج.

| القسم | ملف البيانات (والأنواع) | الصور | الأسعار والمقاسات |
|---|---|---|---|
| الإطلالات | `looks.json` (`types.ts`) | `public/images/looks/` (الأصول: `assets/looks/originals`) | `items[].demoPrice` (ريال يمني)، `items[].sizes`، `items[].productId` (حاليًا `null`) |
| الماركات | `brands.json` (`brand-types.ts`) | `public/images/brands/*.svg` | — |
| علاقة الملابس | `rail.ts` (داخل الكود) | `public/images/rail/` | `tag` (نص بالدولار من العرض التوضيحي) |
| تسوّق حسب القسم | `shop-categories.json` (`category-card-types.ts`) + `categories.ts` (قائمة الأقسام الوحيدة) | `public/images/categories/` | — |
| وصل حديثًا | `new-arrivals.json` (`new-arrivals-types.ts`) | `public/images/new-arrivals/` (مودل + قطعة لكل لون) | `items[].price`، `items[].sizes` (S…XXL) |
| الأحذية | `shoes.json` (`shoes-types.ts`) | `public/images/shoes/` | `shoes[].price`، `shoes[].sizes` (38…47 أوروبي) |
| الآراء والتواصل والفوتر | `closing.json` (`closing-types.ts`) | — | — |
| النموذج الأول (أرشيف) | `src/data/*.ts` | `public/images/{collection,cosmos,hero}` + صور خارجية من Figma | — |

**تنسيق السعر:** `formatYER()` في `src/lib/catalog.ts` يعرض «24,000 ر.ي». الأسعار أرقام صحيحة بالريال اليمني.

## 3. السلة والمفضلة والإدارة الحالية — كيف تعمل وحدودها

### السلة التجريبية — `src/components/store/DemoBag.tsx`

- `DemoBagProvider` يغلّف الصفحة، و`useDemoBag().add(lines)` يضيف أسطرًا بالشكل `{ lookId, itemId, label, size, price, image? }`.
- الأسطر تُحفظ في متصفح الزائر فقط (`localStorage` بالمفتاح `bh-demo-bag`)، ويظهر إشعار «أُضيف ... إلى السلة التجريبية».
- **ما لا يوجد فيها:**
  - صفحة سلة، أو تعديل كمية، أو حذف سطر.
  - حساب ضريبة أو شحن، أو إتمام طلب.
  - أي اتصال بالخادم.
- زر السلة في الهيدر يعرض العدد فقط ولا يفتح شيئًا.
- قسم «وصل حديثًا» فيه لوحة صغيرة تعرض الأسطر ومجموعها، مع ملاحظة «لا يُرسل أي طلب شراء».
- **من يضيف إلى السلة:**
  - فاتورة الإطلالة: `src/components/hero/LookReceipt.tsx`.
  - وصل حديثًا: `VirtualFit.tsx`.
  - الأحذية: `ShoeShelf.tsx`.
  - في وصل حديثًا والأحذية، المقاس إلزامي قبل الإضافة.

### المفضلة والبحث والحساب والقائمة

أزرار **المفضلة والبحث والحساب** في الهيدر، وزر **القائمة** على الهاتف، **شكلية بلا وظيفة**: لا يوجد لها منطق أو صفحات. على الهاتف تظهر روابط الأقسام في الفوتر، لكن قائمة الهيدر لا تفتح.

### أدوات الإدارة المحلية — `src/app/admin/*`، `src/app/api/admin/*`، `src/lib/*-store.ts`

- تعمل فقط في `npm run dev`، وفقط من الجهاز نفسه:
  - `src/lib/admin-guard.ts` يرفض أي طلب ليس من localhost، فتعيد صفحات الإدارة 404 ومسارات API ‏403.
  - في بناء الإنتاج تعيد كلها 404.
- تكتب مباشرة في ملفات `src/content/*.json` على القرص، كتابةً ذرية بعد تحقق شامل.
- ترفع الصور إلى `public/images/...` بأسماء جديدة ولا تستبدل القديمة.
- **لا يوجد:** تسجيل دخول أو مستخدمون أو صلاحيات أو سجل تعديلات أو قاعدة بيانات أو رفع إلى تخزين سحابي. الصور المستبدلة تبقى في المجلد.
- **⚠️ ليست بديلًا للوحة تحكم إنتاجية.** لا يمكن استخدامها على استضافة حقيقية (القرص غالبًا للقراءة فقط، ولا توجد حماية مستخدمين). اعتبرها أداة تحرير محتوى أثناء التطوير، ونموذجًا لقواعد التحقق التي يجب نقلها إلى لوحة التحكم الحقيقية.

## 4. نقاط الربط مع أنظمة الشركة

لم تُزوَّد الحزمة بأي توثيق لواجهات برمجة الشركة (API) أو بيانات دخول، ولم يُنفَّذ أي ربط. هذه هي **أماكن** الربط المقترحة في الكود فقط:

| الحاجة | المكان الحالي في الكود | ما يلزم |
|---|---|---|
| **المنتجات والكتالوج** | `src/lib/catalog.ts` (`resolvePrice()` يعيد `demoPrice` دائمًا مع `isDemo: true`)؛ حقل `productId` في `looks.json`؛ معرفات `items[].id` في `new-arrivals.json` و`shoes[].id` في `shoes.json`؛ معرفات الأقسام في `src/content/categories.ts` | ربط كل معرف بمنتج/SKU حقيقي. يُربط `productId` في الإطلالات فقط بعد مطابقة القطعة في الصورة مع صورة المنتج الحقيقي |
| **المخزون والمقاسات** | مصفوفات `sizes` الثابتة في ملفات JSON | جلب المقاسات المتوفرة من المخزون، وتعطيل غير المتوفر، وتحديد الحالة عند النفاد |
| **الأسعار** | `price` و`demoPrice` في JSON، و`formatYER()` | أسعار حقيقية من الخادم، مع تحديد العملة والعروض. أزل وسوم «تجريبي» عند الربط |
| **صفحات الأقسام** | `src/app/categories/[slug]/page.tsx` (بلا منتجات عمدًا) | شبكة منتجات القسم، والتصفية، وصفحة المنتج |
| **السلة** | `DemoBag.tsx` (دالة `add` وحالة `localStorage`) | سلة على الخادم أو مرتبطة بالحساب، وصفحة سلة، وتعديل الكمية والحذف. مكوّنات الأقسام تستدعي `add()` فقط، فيكفي استبدال تنفيذها |
| **الحسابات** | زر الحساب في `StoreHeader.tsx` (شكلي) | تسجيل دخول ومصادقة على الخادم |
| **المفضلة والبحث** | أزرار شكلية في `StoreHeader.tsx` | تنفيذ كامل |
| **الطلبات** | غير موجودة | إنشاء الطلب والتحقق من السعر والمخزون **على الخادم** |
| **الدفع والخدمات المالية** | غير موجودة، ولا يوجد أي كود دفع | تكامل مع مزوّد دفع على الخادم فقط، دون أي مفتاح سري في الواجهة. الأسعار من الواجهة لا يُعتمد عليها في الحساب |
| **لوحة التحكم** | أدوات `/admin/*` المحلية | لوحة إنتاجية بصلاحيات، وقاعدة بيانات أو CMS بدل ملفات JSON، وتخزين صور (CDN). أعد استخدام قواعد التحقق الموجودة في `src/lib/*-store.ts` |
| **معلومات التواصل** | `closing.json` (الهاتف، واتساب، العنوان، رابط الخريطة، حسابات التواصل) | يمكن نقلها إلى إعدادات لوحة التحكم |

**مبدأ مهم في التصميم الحالي:** مكوّنات الحركة لا تعرف مصدر البيانات. تقرأ أشكالًا معرّفة في `*-types.ts`. عند الربط، حوّل استجابة الـ API إلى هذه الأشكال نفسها (في خادم Next أو في طبقة adapter)، فلا تحتاج لتعديل كود الحركة.

## 6. المشكلات والتحذيرات المعروفة

1. **تحذير Hydration في الهيرو** عند تفعيل «تقليل الحركة» في النظام: زر إيقاف العرض التلقائي في `LooksHero` يُرسم في الخادم ولا يُرسم في العميل. React يعيد رسم الشجرة ويعمل القسم، لكن يظهر خطأ في الكونسول. الحل: قرار الحركة يجب أن ينتظر التحميل في العميل.
2. **تحذير ESLint قديم** في `src/components/ui/product-rail-gallery.tsx:1134` (`react-hooks/exhaustive-deps`): لا يمنع البناء.
3. **أزرار الهيدر الشكلية** (القائمة، البحث، الحساب، المفضلة، السلة): انظر القسم 3.
4. **النموذج الأول `/prototype-v1`** أرشيف. يعتمد على صور مستضافة خارجيًا على Figma (`src/data/site.ts`)، ونصوصه إنجليزية تجريبية. يمكن حذفه عند الاستغناء عنه مع صوره (`public/images/{collection,cosmos,hero}`)، وبعض المكوّنات (`HeroSection`، `CosmosGallerySection`، `collection-surfer`، `AtmosphericBackground`، `AboutSection`، `ServicesSection`، `MarqueeSection`) لا يستخدمها غيره.
5. **البناء يحتاج إنترنت** لتحميل خطوط Google (`next/font/google`).
6. **المحتوى يُقرأ وقت البناء:** تعديل JSON في الإنتاج يحتاج إعادة بناء ونشر.
7. **حجم الأصول:** `assets/` (~84MB) و`brand/` (~64MB) أصول أصلية للتعديل ولا تُنشر. ملف `.vercelignore` الموجود يستبعدها هي وأدوات الإدارة من أي نشر تجريبي.
8. **ملف بلا امتداد باسم يونيكود غير مألوف** في `brand/images/` (يبدأ بـ «𝗔 𝗡𝗲𝘄 𝗖𝗵𝗮𝗻𝗴𝗲...»): صورة مرجعية لحذاء شتوي، وقد تتعذر قراءته في بعض الأدوات. غير مستخدم في الموقع.
9. **`AGENTS.md`** يُنشئه `next dev` تلقائيًا في جذر المشروع (تعليمات لأدوات الذكاء الاصطناعي). يمكن تجاهله أو إضافته إلى `.gitignore`.
10. **الاختبارات الآلية:** لا يوجد إطار اختبارات في المشروع. الأقسام الجديدة اختُبرت يدويًا وعبر سكربتات متصفح خارج المشروع (غير مضمنة).
11. **ظهور الصورة عند النقر في الأحذية** يعتمد على `img.decode()` قبل التقريب. في المتصفحات القديمة جدًا قد يتأخر التقريب قليلًا.
12. **مسارات ويندوز الطويلة:** أحد ملفات `brand/images/` (صورة مرجعية من SHEIN) اسمه طويل جدًا. فك الضغط في مسار قصير (مثل `C:\dev\`)، أو فعّل دعم المسارات الطويلة في ويندوز، وإلا قد تتخطاه بعض أدوات فك الضغط. الملف غير مستخدم في الموقع.
13. **تحذير `npm ci` مع npm 11:** تظهر رسالة أن `unrs-resolver` (من اعتماديات ESLint) لديه سكربت `postinstall` غير معتمد. التثبيت والفحص والبناء نجحت رغم ذلك. يمكن اعتماده بـ `npm install-scripts approve unrs-resolver` إن رغبت.

## 7. ما يختلف في هذه الحزمة عن مجلد العمل الأصلي

الحزمة نسخة مستقلة، ولم يُعدَّل المشروع الأصلي.

- **أُضيفت:** `README.md` (استبدل README الافتراضي لـ create-next-app)، و`HANDOFF.md`، و`THIRD-PARTY.md`، و`.env.example`.
- **عُدِّل:** `.gitignore` بإضافة سطر `!.env.example` حتى يُتتبَّع ملف المثال، بينما تبقى ملفات `.env` الحقيقية مستبعدة.
- **استُبعدت:**
  - `node_modules/` و`.next/`: اعتماديات وناتج بناء، يُعاد إنشاؤها بـ `npm ci` و`npm run build`.
  - `.git/`: سجل Git، لأنه يحتوي بيانات المؤلف. الحزمة لقطة بلا تاريخ، فابدأ مستودعًا جديدًا.
  - `.claude/` و`.mcp.json` و`CLAUDE.md` و`AGENTS.md`: إعدادات أدوات الذكاء الاصطناعي المستخدمة أثناء التطوير.
  - `tsconfig.tsbuildinfo` و`next-env.d.ts`: ملفات مولّدة.
  - مجلدات `assets/*/review*`: لقطات ومقاطع مراجعة مؤقتة.
- لا توجد في الحزمة أي مفاتيح API أو كلمات مرور أو رموز دخول أو ملفات `.env` فعلية. فُحصت الحزمة بحثًا عنها.

  - الأقسام كلها ظاهرة، والعرض المنحني يرسم بـ WebGL.
  - مسح «وصل حديثًا» يبدّل المودل، وتسلسل إضاءة الأحذية يكتمل.
  - تقريب الأحذية والتالي والإغلاق تعمل.
  - صفحات الأقسام و`robots.txt` تستجيب 200، والخطوط محمّلة.
  - لا طلبات لمواقع خارجية، ولا أخطاء في الكونسول.
  - أدوات الإدارة 404 كما هو متوقع.
- **وضع التطوير (`npm run dev`):**
  - نفس فحوص الواجهة ناجحة.
  - الإدارة تعمل من localhost (200)، وتُرفض من الشبكة: API ‏403 والصفحة 404.
- **سكربتات Python:** تعمل من داخل المجلد دون مسارات خارجه.
- **الأسرار:** لا توجد مفاتيح أو كلمات مرور أو رموز أو بريد أو مسارات جهاز المطوّر الأصلي.

## 9. للبدء

1. ثبّت Node 22 أو 24 وnpm.
2. نفّذ `npm ci` ثم `npm run dev` وافتح http://localhost:3000.
3. اقرأ الأقسام 3 و4 و5 أعلاه قبل أي ربط.
4. ابدأ مستودع Git جديدًا. يُفضَّل عدم إدخال `assets/` و`brand/` في المستودع الرئيسي، أو استخدام Git LFS لها، لأن حجمهما كبير.
